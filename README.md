# PCBLoop

**用对话推进 PCB 设计，让每次协作都有清晰的依据、检查与交接。**

[English](README.en.md) · [安装与使用](docs/skill.md) · [项目架构](docs/architecture.md) · [数据规范](docs/dataset.md) · [路线图](ROADMAP.md) · [参与贡献](CONTRIBUTING.md)

PCBLoop 是一个面向 AI 辅助 PCB 设计的开源项目。我们将实际人机协作中积累的方法整理成可安装的 **Skill**，帮助 AI 核实工程状态、理解修改边界、分批推进任务，并留下可核对的检查记录和续接资料。

你可以用它协助器件整理、封装与引脚网络核查、布局布线规划，以及 DRC 问题处理。每次只需说明工程位置、任务目标和允许修改的范围，便能复用这套流程，减少重复交代规则和恢复上下文的负担。

当前版本为 **`v0.2.0-skill`**。已提供协作流程 Skill、安装器、样本格式草案和本地验证工具；实际 CAD 读写需要另外连接设计工具，首个计划集成的平台是嘉立创EDA专业版。

## 这个 Skill 能帮你做什么

- **先认对工程**：核对目标 PCB、器件版本、封装与引脚网络，避免沿用过时信息或选错设计。
- **按你的分工推进**：只做前期准备，或继续布局布线，都以本轮任务和授权为准。
- **保护已有成果**：要求修改前检查现场变化，保留人工工作，不直接重放旧脚本或覆盖历史快照。
- **联合规划，分批执行**：结合电流路径、信号回流和模块依赖安排任务，连续推进，并在模块间保存检查点。
- **如实说明检查结果**：区分未连接、间距、短路与网表问题，不把 DRC 数量下降等同于整板合格。
- **方便下次接着做**：记录实际修改、当前版本和剩余任务，让后续对话有据可查。

这些是 Skill 对 AI 的执行指引。实际效果仍取决于模型、CAD 工具能力、工程条件与人工评审，尚未完成多模型、多板卡的独立行为评测。

## 快速开始

需要 Python 3.10 或更新版本。克隆仓库后安装 Skill：

```bash
git clone https://github.com/3344259705-prog/ai-PCB.git
cd ai-PCB
python tools/install_skill.py
```

安装器仅使用 Python 标准库，将 Skill 复制到个人技能目录；遇到不同版本或个人修改时会拒绝覆盖。

安装后新建一个 Codex 对话，提供实际工程位置，例如：

```text
使用 $pcbloop。
工程位置：[填写实际工程目录或目标 PCB]。
先读取最新交接报告并核对当前工程状态。
保留元件型号、封装、引脚网络和已有线路，允许布局与铜图优化。
按优先级连续处理未完成模块，每模块保存并检查，结束时生成交接报告。
```

如果你准备自己布局布线，也可以明确限定任务：

```text
使用 $pcbloop。这次只整理指定版本的器件，核对引脚网络和飞线显示。
保留现有布局，不布线。发现需要修改电路的问题时，先列出差异与依据。
```

安装不会连接 CAD、授予编辑权限或上传工程。自定义目录、升级说明和更多续接示例见[使用指南](docs/skill.md)。

独立 CAD 适配器、自动状态保护与回滚、自动布线器、社区数据库及模型训练服务尚未实现。Skill 中规定的检查步骤，不代表仓库已经提供相应的自动化检查器。

## 从个人协作走向社区经验

我们的长期目标，是让经过授权和验证的设计经验能够被更多人复用。成功方案值得记录，失败尝试、人工纠正和适用条件也同样重要。

计划中的协作闭环如下：

```mermaid
flowchart LR
  U[用户目标与约束] --> A[读取工程并规划]
  K[经审核的案例检索] --> A
  A --> G[授权与状态核对]
  G --> C[CAD 工具执行]
  C --> V[差异 网络与工程检查]
  V --> H[人工评审与检查点]
  H --> D[本地案例记录]
  D --> R[选择共享 脱敏与质量审核]
  R --> K
```

我们会先完善工作流程、工具与案例检索，再考虑独立的模型训练实验。训练需要明确的来源与用途许可、固定的数据版本，以及按项目族划分的评测集。上传案例不会自动更新模型参数，样本数量也不能代替质量验证。具体安排见[路线图](ROADMAP.md)。

## 检查样本与运行测试

开发依赖与 Skill 安装相互独立。建议在 Python 虚拟环境中执行：

```bash
python -m pip install -r requirements-dev.txt
python tools/validate_episode.py examples/synthetic_episode.json
python tools/validate_episode.py --for-publication examples/synthetic_episode.json
python -m unittest discover -s tests -v
```

验证工具只检查 JSON 格式和部分元数据约定，不读取 CAD 几何，也不验证真实 DRC、电气性能、来源权利或制造条件。用户接受、CAD 检查通过和实板验证应分别记录，不能合并成一个“成功”标签。详见[验证工具说明](docs/validator.md)与[数据规范](docs/dataset.md)。

## 数据与隐私

本仓库不包含真实 PCB 工程或私人聊天原文，没有后台采集、遥测或自动上传。公开分享、案例检索和模型训练分别需要对应授权。

请勿提交访问令牌、个人信息、客户资料或未经许可的第三方工程；不采集模型私有思维链。真实案例的采集与审核流程仍在规划中。
