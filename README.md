# PCBLoop

**用对话协作设计PCB，让经过验证的工程经验形成可复用的社区知识。**

[English](README.en.md) · [安装Skill](docs/skill.md) · [架构](docs/architecture.md) · [数据规范](docs/dataset.md) · [路线图](ROADMAP.md) · [参与贡献](CONTRIBUTING.md)

> 当前阶段：`v0.2.0-skill`——可安装的PCB协作流程Skill、样本规范与本地验证工具。
> **尚未实现可运行的CAD适配器、自动布线插件、社区数据库或模型训练平台。**

## 我们要解决什么

通过对话让AI理解电路、读取真实CAD状态、在用户授权内提出并执行修改，再保存检查点、验证结果和人工反馈。
把有效方法、失败方案和人工纠正整理成有证据的案例，帮助后续用户更有效地使用AI。
目标首先是可审查、可恢复的协作流程，而不是承诺任意PCB一键完成。

## 工作闭环（目标架构）

```mermaid
flowchart LR
  U[用户任务与约束] --> A[AI读取工程并规划]
  K[审核后的案例检索] --> A
  A --> G[授权与状态保护]
  G --> C[CAD适配器执行]
  C --> V[差异 网络 DRC与工程检查]
  V --> H[人工反馈与检查点]
  H --> D[本地样本]
  D --> R[选择共享 脱敏 来源与质量审核]
  R --> K
```

首期计划对接嘉立创EDA专业版。模型负责理解和规划，CAD/几何工具负责实际操作，检查器与人工评审负责验证。
客户端不支持的接口不能假装已支持；用户正在编辑时也不能用旧快照覆盖现场。

## 怎样让AI越来越有用

- **先改善检索与工具**：审核后的案例帮助后续任务选择方法、避免重复犯错，并改进约束检查与执行策略。
- **再考虑模型训练**：选择有授权、质量合格的轨迹，形成固定数据版本，单独训练并在未见过的项目上评测。
- **分开衡量**：检索效果、模型判断、几何布线求解和实板性能不是同一件事。

上传聊天记录不会自动更新模型参数，样本数量增长也不等于性能必然提升。

本仓库不包含真实PCB工程或真实聊天原文，没有后台采集、遥测或自动上传。
案例中的数字都是演示数据，不代表实际PCB测量。

## 作为Skill使用

仓库提供可安装的[`pcbloop` Skill](skills/pcbloop/SKILL.md)，将现场核对、授权边界、联合规划、连续多模块、检查点与跨会话交接整理为AI执行指令。

```bash
python tools/install_skill.py
```

安装后新建Codex对话，输入：

```text
使用 $pcbloop。先读取我的PCB工程及最新交接报告，核对实际状态，
保留现有器件、网络和人工布线，只继续未完成模块。
```

安装器只复制本地Skill，不连接或修改CAD。实际操作需要另行可用的CAD工具；Skill中的状态保护与验证是执行要求，不是已经实现的CAD自动守卫。详见[安装、调用与续接示例](docs/skill.md)。

## 快速检查示例

需要Python 3.10或更新版本。建议先创建虚拟环境，再在环境中执行：

```bash
python -m pip install -r requirements-dev.txt
python tools/validate_episode.py examples/synthetic_episode.json
python tools/validate_episode.py --for-publication examples/synthetic_episode.json
python -m unittest discover -s tests -v
```

检查工具只读取JSON：验证Schema，以及授权动作、发布标记和结果标签的部分一致性。
**它不会读取或修改CAD，不能验证真实DRC、电气正确性、来源权利、制造或上电安全。**

具体检查条件及边界见[验证工具说明](docs/validator.md)。

## 样本需要什么

任务与约束、CAD和工具版本、前后状态引用、用户授权、实际差异、检查结果、人工反馈，以及来源和使用权限。
详细说明见[数据规范](docs/dataset.md)。不采集模型私有思维链，也不应上传访问令牌、个人信息或未获授权的工程。

用户接受、CAD检查通过和实板验证必须使用不同标签。
评价不能只看DRC总数：必须区分短路、间距、未连接、规则配置、回流及功率路径等问题。
